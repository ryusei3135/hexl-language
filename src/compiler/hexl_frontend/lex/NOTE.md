# NOTE: `{}`形式の関数マクロ(`#define M{..}`)

プリプロセッサ(`preprocessor.rs`)の`#define`に、`()`の代わりに`{}`で引数を囲む
関数形式マクロを追加した(2026-10-24)。全体の仕様は`PREPROCESSOR.md`を参照。

## 書き方
```
#define M{a, b} a = b + 1      // 仮引数を{}で囲む(1行の本体)
#define M{} {{                 // 引数なし。本体は{{ .. }}で複数行にできる
  expr = 10
  expr2 = 10
}}

#M { x, 2 }                    // x = 2 + 1
#M {}                          // 引数なしの呼び出し
```
- `()`形式との違いは、**定義の`( )`が`{ }`になる**ことと、
  **呼び出しが`#M { .. }`になる**ことだけ。展開の手順(実引数の先展開 → 仮引数の置き換え →
  再展開)、`{{ .. }}`の複数行の本体、同名の再定義は無視される点などは`()`形式と同じ。
- 定義: 名前の**直後(空白なし)**に`{`を書く。`#define A {1}`のように空白があれば値のマクロ。
  `#define A{{ .. }}`のように`{{`が続く形は、従来どおり複数行の値のマクロ(`{}`形式ではない)。
- 呼び出し: `#M`のあとに`{ 実引数, .. }`を書く。名前と`{`の間の**空白・タブは省略も複数も可**
  (`#M { x }` / `#M{x}`)。改行は挟めない。
- 実引数は`{`と対応する`}`の間で、括弧(`()` `[]` `{}`)の外側の`,`で区切る
  (`#ADD { f(1, 2), 3 }`の実引数は`f(1, 2)`と`3`)。文字列リテラルの中は区切りにしない。
- `{}`形式のマクロを`#M(1)`と呼ぶ、`()`形式のマクロを`#M { 1 }`と呼ぶと`panic`する
  (定義と呼び出しの括弧は一致させる)。
- 次の場合も`panic`する: 実引数の数が仮引数と違う、仮引数が識別子でない・重複、
  `}`で閉じていない、`{`の代わりに別の括弧で閉じている(`#M { 1 )`)。
- 行番号の扱いは`()`形式と同じ(呼び出しが読み飛ばした改行は展開結果の後ろに出す)。

## 実装の場所(`preprocessor.rs`、`preprocessor/define.rs`)
(2026-10-24にファイルを命令ごとに分割した。`PreprocKind`は`preprocessor.rs`、それ以外は`define.rs`)
| 処理 | 変更 |
|------|------|
| `PreprocKind::DefineFn` | `brace: bool`を追加(`true`なら`{}`形式) |
| `parse_define_fn` | 名前の直後が`{`のときも関数形式として読む(`{{`は除く)。閉じ括弧は`}` |
| `is_define_header` | `NAME{arg, ..}`も見出しとして認める(`{{ .. }}`の複数行の定義用) |
| `parse_macro_args` | `brace`引数を追加。`{`形式は名前の後ろの空白・タブを読み飛ばし、`}`で閉じる |
| 呼び出し側(`preprocess_text` / `expand_inline`) | `brace`を`parse_macro_args`へ渡す |

`parse_macro_args`は、開き括弧と対応しない閉じ括弧(`#F(1}`)も`panic`にするようにした。
これは`()`形式にも効く(以前は何でも閉じ括弧として受け付けていた)。

## 注意・今後
- 展開はテキストの置き換えで、`{}`は展開結果に自動では付かない(`()`形式と同じ)。
- 実引数に`}`だけが単独で現れる(`#M { } }`)ような書き方はできない(対応する括弧で数える)。
- テストは`lexer.rs`の`check_preprocessor_brace_fn_macro*`にある。
