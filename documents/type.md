## 範囲付きポインタ

範囲付きポインタは、ポインタがアクセス可能なメモリ範囲をコンパイル時に管理する機能である。

通常のポインタはアドレスだけを保持するが、範囲付きポインタはポインタの位置に加えて、そのポインタが扱える範囲を持つ。

これにより、ポインタ演算やメモリアクセスによる範囲外アクセスをコンパイル時に検出する。

### 基本概念

範囲付きポインタは、以下の3つの位置によって範囲を表す。

```text
begin <= position <= end
```

ここで、

* `begin` は範囲の開始位置
* `position` は現在のポインタ位置
* `end` は範囲の終了位置

を表す。

ただし、**メモリへのアクセスが可能なのは `end` より前まで**である。

```text
begin <= position < end
```

したがって、`end` は範囲内を表す境界位置ではあるが、`end` の位置に対してメモリアクセスを行うことはできない。

### 範囲外への移動

ポインタを移動する場合、移動後の位置が範囲内であることが必要である。

```text
begin <= position <= end
```

例えば、5個の要素を持つ配列を考える。

```text
a: [int 5]
```

この配列の範囲を、

```text
0 <= p <= 5
```

として管理する。

要素へのアクセスは、

```text
0 <= p < 5
```

でなければならない。

そのため、5番目の要素の次を指す位置までポインタを移動することは可能だが、その位置から値を読み書きすることはできない。

### ポインタ演算

範囲付きポインタに対する加算・減算は、移動後の位置が範囲内であることをコンパイラが確認できる場合のみ許可される。

```text
p + 1
p - 1
```

などの演算では、結果が

```text
begin <= position <= end
```

を満たす必要がある。

範囲外になることがコンパイル時に判明する場合はコンパイルエラーとなる。

また、コンパイラが範囲内であることを証明できない場合も、範囲外アクセスにつながる可能性があるため許可しない。

### 可変ポインタ

可変ポインタは、ポインタ自身の位置を変更できるポインタである。

可変ポインタでは、以下のような操作を許可する。

```text
p += 1
p -= 1
```

移動後の位置が範囲内であることが必要である。

可変ポインタは、同時に複数存在させることを制限する。

基本的に、同一の範囲に対して存在できる可変ポインタは1つまでとする。

### 不変ポインタ

不変ポインタは、ポインタ自身を直接変更しないポインタである。

不変ポインタでは、

```text
p + 1
p - 1
```

のように、元のポインタを変更せず、新しい位置を表す式を生成する。

不変ポインタそのものの位置を変更する操作は許可しない。

```text
p += 1
```

のような操作はできない。

### 不変ポインタのコピー

不変ポインタは複数コピーすることができる。

```text
a = p
b = p
c = p
```

のように、同一の不変ポインタから複数の不変ポインタを生成できる。

不変ポインタはメモリを書き換える権限を持たないため、複数存在しても可変アクセスの競合を発生させない。

### 可変ポインタのコピー

可変ポインタは通常のコピーを許可しない。

可変ポインタを複製すると、同じメモリ範囲を変更できる可変ポインタが複数存在してしまうためである。

可変ポインタから別の可変ポインタを作成する場合は、明示的な操作を必要とする。

```text
b = *mut p
```

この操作によって可変ポインタの可変性を移す。

元の `p` は、その後可変ポインタとして使用できなくなる。

### `move` と可変ポインタ

可変ポインタの所有権を `move` によって移動することができる。

```text
b = move p
```

この場合、可変ポインタとしての権限は `b` に移動する。

移動元の `p` は可変ポインタとして使用できない。

### 不変参照

範囲付きポインタから不変参照を作成することができる。

```text
b: int& = p
```

不変参照は対象メモリを読み取ることができるが、対象を書き換えることはできない。

可変ポインタが存在している間でも、不変参照を作成することができる。

ただし、不変参照によって可変ポインタの範囲や権限が変更されることはない。

### 可変参照

可変アクセスを行う場合は可変参照を使用する。

```text
&mut
```

を可変参照として使用する。

可変参照を作成している間は、その対象に対する別の可変アクセスと競合しないように管理する。

### ポインタの分割

範囲付きポインタは、アクセス可能な範囲を分割することができる。

例えば、

```text
begin ---------------- end
```

という範囲を2つに分割すると、

```text
begin -------- split -------- end
```

それぞれ独立した範囲として扱うことができる。

分割後は、各ポインタが自身に割り当てられた範囲のみを操作できる。

これにより、同じメモリ領域を複数の可変ポインタから同時に操作することを防止する。

### 分割後の元ポインタ

ポインタを分割した場合、元のポインタは可変ポインタとして使用できなくなる。

元のポインタについては、不変参照としての利用のみが可能となる。

```text
p
 ↓
┌────────────────────┐
│       memory       │
└────────────────────┘

split

p1                  p2
│                   │
├────────┐ ┌────────┤
         │ │
      separate ranges
```

分割された範囲は、それぞれ独立した可変ポインタとして扱う。

### 分割範囲の結合

分割された範囲は、条件を満たす場合に再び結合できる。

結合すると、分割前の大きな範囲を持つポインタとして扱える。

ただし、分割した範囲の結合順序を変更することはできない。

これは、隣接関係を保持したまま範囲を再構築するためである。

```text
A | B | C
```

を分割した場合、

```text
A + B + C
```

という元の順序で結合する必要がある。

```text
A + C + B
```

のように順序を入れ替えて結合することはできない。

### 範囲の代入

不変ポインタが保持する範囲は、条件を満たす場合に別の範囲へ変更できる。

ただし、変更後の範囲についても、そのポインタがアクセス可能な範囲であることがコンパイル時に確認できなければならない。

可変ポインタについては、可変アクセス権限と範囲の整合性を維持する必要があるため、単純な範囲変更を許可しない。

### 範囲とアクセス

範囲付きポインタによるメモリアクセスは、

```text
begin <= position < end
```

を満たす必要がある。

例えば、

```text
p = end
```

は有効な移動であるが、

```text
*p
```

は許可されない。

これは、`end` を配列の末尾を示す境界として利用できるようにするためである。

### 範囲と契約

契約付きポインタと範囲付きポインタを組み合わせることができる。

```text
p: int* must free
```

のような契約に範囲情報を持たせる場合、契約の有効期間中は範囲情報も維持される。

契約が終了した場合、その契約に依存するポインタや参照も使用できなくなる。

### 範囲付きポインタの原則

範囲付きポインタでは、以下を基本原則とする。

1. ポインタはアクセス可能な範囲を持つ。
2. ポインタの移動は `begin <= position <= end` の範囲内でなければならない。
3. メモリアクセスは `begin <= position < end` の範囲内でなければならない。
4. 範囲外になるポインタ演算は許可しない。
5. コンパイラが範囲内であることを証明できない演算は許可しない。
6. 可変ポインタは同一範囲に対して原則1つまでとする。
7. 不変ポインタは複数コピーできる。
8. 可変ポインタの複製には明示的な操作を必要とする。
9. `move` によって可変ポインタの権限を移動できる。
10. ポインタを分割すると、元のポインタは可変ポインタとして使用できない。
11. 分割された範囲は、それぞれ独立した範囲として扱う。
12. 分割された範囲を結合する場合、元の順序を維持する。
13. 範囲情報はポインタの安全性を静的に検査するために使用する。
